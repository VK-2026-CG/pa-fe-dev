# AGENTS.md — pruaction-app

The **shared, tool-neutral contract** for every coding agent and contributor.
Claude (`CLAUDE.md`, `.claude/rules/*`) and GitHub Copilot
(`.github/copilot-instructions.md`, `.github/instructions/*`) both defer to this
file — they only describe how each tool applies these rules. If a tool-specific
file disagrees with this one, this one wins.

## Source of truth (in order)
1. `vendor/spec/*` — VM types, i18n bundle, MY screen config (synced from
   `pruaction-spec`; see that repo's AGENTS.md §0 for full precedence)
2. This file — engineering rules
3. `src/lib/compose/*` — BFF composition, unit-tested against the VMs
4. `tests/*` — behavior lock; test names carry the spec AC ids

Reference documentation (rationale, not rules):
`docs/architecture/README.md` · `docs/architecture/decisions/` ·
`docs/security/README.md` · `docs/testing/playwright.md` ·
`docs/design/figma-measurements.md`

## Spec-agent handoff
- Preferred human commands are `/develop-frontend <SPEC-ID-or-JIRA-ID>` and
  `/fix-frontend-bug <BUG-JIRA-ID> [SPEC-ID]` in Copilot or Claude. Agents resolve
  `PruactionSpec/work-items` and run sync/receipt/validation npm automation
  internally. Never guess when one Jira maps to several specs.
- Inbound handoffs live in `handoffs/inbox/spec/` and are read-only. Consume
  only `READY` handoffs pinned to a full spec commit.
- Run `SPEC_REF=<handoff.spec.commit> HANDOFF_REF=<handoff-publication-commit>
  npm run sync:specs`; `vendor/spec/SPEC_COMMIT` must match before implementation,
  while `HANDOFF_COMMIT` records instruction publication. A dirty `DRAFT` is planning input only.
- Implement only `consumers.frontend.requiredActions`; contract gaps produce
  a `BLOCKED` receipt, never locally invented VMs, copy, fields, or endpoints.
- Maintain the correlated file under `handoffs/outbox/receipts/` with BFF/UI
  operation coverage, AC-named unit/API/E2E evidence, explicit URL/build
  commands, and gaps.
- Run `npm run handoff:validate`. Promote to `COMPLETE` only after spec and
  Web commits are immutable, all required ACs pass, the worktree is clean, and
  gaps are empty; copy the receipt to
  `PruactionSpec/handoffs/receipts/frontend/`.
- Bug work classifies and localizes the first contract divergence before edits.
  `SPEC_DEFECT` and `NEW_REQUIREMENT` require `/update-spec`; upstream backend or
  data defects must not be hidden with UI/BFF fallbacks. Regression tests name
  the governing AC and bug Jira ID.

## Screen-ID packages, reuse and Spec-owned assets
- For detailed UI work, start from the named package under
  `vendor/spec/domains/<domain>/screens/<HumanName>_<ID>/` and its human-readable
  summary. Implement only when the handoff and screen status permit it.
- Search vendored common/domain registries and inspect mapped existing exports
  before creating components, behaviors, BFF helpers, fixtures, icons or images.
  Follow the package's reuse decisions; return missing/incorrect decisions to
  Spec rather than duplicating code.
- Assets under `public/spec-assets/` are generated by immutable Spec sync.
  Never hand-edit or replace them. Use the typed registry generated at
  `src/generated/spec-assets.ts` and validate checksums with
  `npm run assets:validate`.
- No raw fonts, colors, gradients, shadows, borders, radii, spacing, icons,
  effects or motion in a screen. Resolve every visible property through approved
  Spec/DLS contracts. A blocked/missing baseline prevents pixel-perfect or
  COMPLETE claims.

## Hard rules
- **No literal UI strings.** Every user-visible string goes through
  `t('insights.…')` from the vendored bundle; `tests/unit/i18n.spec.ts` scans src
  and fails on unknown keys. Need new copy → add the key to BOTH
  `vendor/spec/en.json` and the Spec domain content bundles under `domains/<domain>/content/en.json` (lockstep).
- **No raw colors/sizes outside `src/dls-stub/dls.css`** — that file is the DLS
  token stub and the only place values may live. `src/app/globals.css` is a
  single `@import` of it and must stay that way.
- **VMs are imported, never redeclared.** Composers return types from
  `@spec/performance-vm` so contract drift fails `npm run typecheck`.
- **Money is a decimal string** end to end; format via `src/lib/format.ts`
  (string/cents math). `parseFloat` on money for display is a review-reject.
- **Sections render in BFF order**; unknown section types/ids are skipped,
  never errored (AC-P4-02-07). Widgets read `DeltaVM.display` — they never
  infer units (D-10).
- **Entitlement mirrors D-14** in `src/lib/bff.ts` (TEAM ⇒ leader; GROUP ⇒
  P2 → 403 BFF-4031/4032). Don't weaken guards to make a screen work, and never
  move an authorization decision into the UI only.
- Draft screens (S-P4-05 Benefits, S-P4-06 Comp&Ben) ride proposed VMs
  behind `/api/bff/v1/{benefits,compensation}` stubs marked `draft: true`
  (OQ-17/18) — flag any extension as a spec question first.
- SCHEME prefs don't exist yet (OQ-20): SCHEME lenses use catalog defaults;
  Customize edits the STANDARD doc per scope only.
- **Never claim security posture this repo doesn't have.** Auth is a stub
  `x-persona` header (client-side `localStorage`, no cookie since ADR 0004);
  CSRF, CSP, rate limiting and IdP are not implemented. See
  `docs/security/README.md` before writing anything about security.

## Definition of done for a screen change
Typecheck green · `npm run test:unit` green (incl. the i18n scan) ·
`npm run test:e2e` green · every touched AC has a
test named after it · `npm run handoff:validate` green · receipt updated · `npm run build` clean · zero console errors in the flows
you touched (the e2e console watcher asserts this). BFF contract/entitlement
changes are verified in `pa-be-dev` (`npm test` there), not here.

## Testing — Playwright only (no Vitest, no shell smoke)
Full guide: `docs/testing/playwright.md` · rationale: ADR 0003.

Three projects in one runner, configured in `playwright.config.ts`:
- `tests/unit/` — **pure module tests** (composers, formatters, LBU config, CDK
  registry, i18n key scan). No browser, no servers: run with
  `npm run test:unit` (sets `PW_SKIP_WEBSERVER=1`).
- `tests/api/` — **BFF contract + entitlement tests** via the `request`
  fixture. This replaces the old `scripts/smoke.sh`; keep the AC ids in the
  test titles.
- `tests/e2e/` — **browser journeys** on the 375-base mobile shell. Prefer
  semantic locators (`getByRole`, `getByText`) over CSS; add `data-testid` only
  when repeated cards can't be addressed by role/name. Scope locators inside
  overlays — a sheet backdrop intercepts clicks.
- `tests/support/` — persona cookies/headers, API helpers, console watcher.

Rules:
- **Never reintroduce `vitest` or `scripts/smoke.sh`.**
- Assert i18n **values from `vendor/spec/en.json`**, never invented copy
  (period chips are `MTD`/`QTD`/`YTD`, not "Month to Date").
- State-mutating suites (customize, feedback) use `test.describe.serial` — the
  stub domain service holds mutable preferences.
- `webServer.reuseExistingServer` is **false on purpose**: a stale process on
  4600/3600 must fail loudly rather than serve a different build. If you see
  "port is already used", kill the squatter — don't flip the flag.
- Playwright owns service orchestration. Never leave `vite` or the domain
  service running after a task.
- Browsers: `npx playwright install chromium` (CI: `--with-deps`).
- `npm test` runs all three projects; the domain service must be built at
  `../pa-be-dev/dist`.

## Routing → CDK layering (multi-LBU)
Rationale: ADR 0001, ADR 0004 · target model: `docs/architecture/frontend-architecture.md`.

- `src/router.tsx` is **routing only**: read route inputs
  (`useSearchParams()`/`useParams()`, the client-side persona), call
  `resolveCdk(feature)`, render it. No fetching, no composition, no market
  branching in the router.
- One country per physical deployment: no shared URL, request-selected country/database, or production localhost fallback. `CONTESTS_API_URL`/`INSIGHTS_API_URL` are pa-be-dev's env vars exclusively — this app never reads them (see ADR 0004).
- `src/config/lbu.ts` is the deployment context: `LBU_CODE` is a **deployment
  constant** (defaults to `my` locally), validated and **fail-closed** on an
  unknown value, and it owns the route/feature manifest.
- `src/cdk/` **is the page layer**: one folder per feature holding the page
  itself — LBU entry first (`performance/PerformanceMY.tsx`), else
  `<feature>/<Feature>Common.tsx` for pages with no market variation. A CDK page
  owns page state, data loading and layout, and composes `src/components`,
  `src/dls-stub` and `src/headless`. It never defines raw colors/sizes.
- This repository currently vendors only MY page specs, so every current page is
  named `<Feature>MY.tsx` and registered under `my`. Introduce a `Common` page
  only when its contract and implementation are identical across multiple
  supported LBUs.
- Page-local building blocks go in `src/cdk/<feature>/parts/`; anything used by
  two or more features moves to `src/components/`.
- Layer order stays: `app` → `cdk` → `components` → `dls-stub` → `headless`.
  Never let a lower layer import an upper one.
- New market = a `config/lbu.ts` entry + its CDKs + its spec. Never fork
  `src/app`, `src/components`, `src/headless` or `src/dls-stub`.

## UI layering: headless/ vs dls-stub/ (DLS swap contract)
Rationale: ADR 0002.

- `src/headless/` — behavior-only primitives (Carousel, Collapse, Tabs, Switch,
  Checkbox, ReorderHandle, Layer, RadioGroup). No colors, sizes, or classes of
  their own.
- `src/dls-stub/` — **the only styled layer**: `dls.css` holds every raw value
  (color tokens ⚠ screenshot-derived; geometry tokens measured from Figma —
  see `docs/design/figma-measurements.md` with node ids), `index.tsx` exports the
  skinned primitives (Icon, Tag, ProgressBar, CarouselRow, BottomSheet, SheetRow,
  ScopePill, ToggleRow, …).
- CDK pages and `src/components/*` compose those two; **to adopt the real
  Prudential DLS, replace `src/dls-stub/` (keeping export names/props) and
  swap the SVGs in `public/icons/` — nothing else changes.**

## Icons

`public/icons/{token}.svg`, rendered by `dls-stub`'s `Icon` (CSS-mask tint).
The Figma layer names identify the glyphs literally (Remix Icon + Material
ids: `trophy-fill`, `hourglass-2-line`, `arrow-right-up-line`, `More Horiz`,
`Thumb Up`, …) — `scripts/copy-icons.mjs` copies exactly those glyphs from
the `remixicon` / `@material-design-icons/svg` dev-deps. To replace with DLS
exports: `public/icons/MANIFEST.json` maps each token to its Figma node id
for `Figma:download_assets`; drop the exported SVG over the file, same name.
